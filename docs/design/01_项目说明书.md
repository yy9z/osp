## 一、项目概述

### 1.1 项目名称

**基于 Agent 的高校校园智能事务处理平台**

### 1.2 项目背景

随着高校信息化建设的持续推进，校园各类业务系统（宿舍管理、二手交易、失物招领、地图导航等）普遍以独立系统形式存在，用户需要在不同页面之间来回切换才能完成事务。传统表单驱动的交互方式门槛高、效率低，且系统间缺乏协同能力。

大语言模型（LLM）技术的成熟，为高校信息系统的智能化升级提供了可行路径。通过引入 Agent 架构，系统可以理解用户自然语言，自动识别意图、提取业务参数、拆解任务、调用底层工具模块，最终为用户提供一站式智能事务处理能力。

本项目在现有校园业务系统的基础上，引入大模型 Agent 作为核心智能中枢，将已有的宿舍管理、二手交易、失物招领、校园导航和消息中心各模块改造为 Agent 可调用的工具集，构建一个面向高校场景的智能事务处理平台。

### 1.3 项目定位

本项目不是单纯的聊天机器人，也不是对原有系统的推翻重做，而是在保留原有校园业务功能的基础上，新增"校园智能助手"作为统一智能入口。

**核心定位：**  
用户输入自然语言 → 智能 Agent 理解意图、拆解任务 → 调用对应业务工具 → 完成事务并返回结构化结果。

## 二、核心创新点

### 创新点一：自然语言驱动校园事务办理

用户无需逐层点击菜单，直接通过自然语言发起事务，系统自动识别意图、拆解参数、调用业务模块。相比传统表单交互，显著降低了操作门槛，提升了事务处理效率。

**示例：**
- 用户输入："我宿舍灯坏了，帮我报修"
- 系统自动识别为"宿舍报修"，提取故障类型，追问缺失的宿舍号，提交工单并返回结果。

### 创新点二：多业务模块的 Agent 工具化集成

将宿舍管理、二手交易、失物招领、校园导航等独立业务模块统一封装为 Agent 可调用工具，形成标准化工具注册表。Agent 根据意图自动选择并编排工具调用，实现跨模块协同。

**示例：**
- 用户输入："帮我找个 100 元以内的二手台灯，从宿舍到卖家怎么走"
- Agent 先调用二手搜索工具，再调用导航工具，最终合并结果回复用户。

### 创新点三：面向校园场景的智能推荐与匹配能力

- **二手商品智能推荐：** 结合语义搜索、预算过滤、距离排序，生成带推荐理由的个性化商品推荐。
- **失物招领智能匹配：** 基于物品语义描述、颜色、地点、时间等维度进行相似度匹配，提升找回率。4 个子模块（寻物公告、招领公告、我的失物、我的招领）分工清晰，覆盖失物事务全生命周期。
- **校园语义导航 Agent 深链：** 支持自然语言地点描述，自动解析为 POI 坐标进行路线规划；Agent 回复的路线结果卡片可直接携带参数跳转导航页，页面自动加载路线，形成「对话结果→地图导航」的完整交互闭环，消除断裂体验。

### 创新点四：上下文感知动态推荐追问

传统聊天助手在完成一次任务后，交互即告终止。本系统在每轮 Agent 回复完成后，基于当前意图和业务结果，由后端动态生成 3～4 个「推荐追问问题」，以可点击气泡的形式展示在对话区。

- 导航场景完成后，推荐「查看路线详情」「换骑行方案」「附近还有哪些…」
- 失物场景完成后，推荐「立即发布寻物信息」「查看相似招领」「补充丢失时间」
- 报修完成后，推荐「查看工单状态」「报修其他设备」

推荐内容与静态硬编码卡片不同，每轮完全由服务端根据上下文生成，驱动用户持续深度使用，体现系统对语境的感知与理解能力。

## 三、系统功能总览

| 模块 | 核心功能 | 是否 Agent 工具 |
|------|----------|----------------|
| 校园智能助手 | 意图识别、参数追问追补、任务拆解与工具调用、结构化结果生成、动态追问推荐 | — （主控） |
| 宿舍事务智能办理 | 自然语言报修、工单查询、宿舍信息查询 | ✓ |
| 二手交易智能推荐 | 语义搜索、预算过滤、推荐理由生成、跳转详情 | ✓ |
| 失物招领智能匹配 | 寻物公告（我的求助）、招领公告（我拾到的）、我的失物、我的招领；Agent自动提取字段、语义匹配、候选提醒 | ✓ |
| 校园语义导航 | 自然语言地点描述、路线规划、Agent深链跳转（携带起终点自动触发路线）、多点导航 | ✓ |
| 消息与提醒 | 工单通知、失物匹配提醒、业务回执 | ✓ |

## 四、总体架构

### 4.1 系统分层

```
┌─────────────────────────────────────────────────────────────┐
│                        前端层（Vue3）                         │
│   首页  │  智能助手页  │  宿舍  │  二手  │  失物  │  导航     │
└───────────────────────────┬─────────────────────────────────┘
                            │ HTTP / WebSocket
┌───────────────────────────▼─────────────────────────────────┐
│                       后端 API 层（Spring Boot）              │
│  AgentController │ DormController │ SecondHandController ...  │
└──────────┬────────────────────────────────────────────────── ┘
           │
┌──────────▼──────────────────────────────────────────────────┐
│                    Agent 核心层                               │
│  IntentService → SlotFillingService → PlannerService         │
│  ToolExecutorService → ResponseGeneratorService              │
└──────────┬──────────────────────────────────────────────────┘
           │  工具调用
┌──────────▼──────────────────────────────────────────────────┐
│                   业务工具层                                   │
│  DormTool │ SecondHandTool │ LostFoundTool │ NavTool │ MsgTool│
└──────────┬──────────────────────────────────────────────────┘
           │
┌──────────▼──────────────────────────────────────────────────┐
│                   数据与外部服务层                             │
│  MySQL │ Redis │ 大模型 API（DeepSeek/通义千问） │ 高德地图 API │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 Agent 工作流

```
用户自然语言输入
       ↓
  意图识别（IntentService）
       ↓
  参数提取（SlotFillingService）
       ↓
  信息完整性校验
   ↙              ↘
完整              缺失
  ↓              追问用户
  ↓                 ↓
任务拆解（PlannerService）
       ↓
  工具执行（ToolExecutorService）
       ↓
  结果汇总（ResponseGeneratorService）
       ↓
  返回自然语言 + 结构化卡片
```

## 五、技术选型

| 层次 | 技术 | 说明 |
|------|------|------|
| 前端 | Vue 3 + Vite + Pinia + Element Plus | 组件化 SPA |
| 后端 | Spring Boot 4.x + MyBatis | 三层架构 |
| Agent | Spring Boot 内嵌（Java 实现） | LLM 调用中枢 |
| 大模型 | GLM-4 / DeepSeek / 通义千问（OpenAI 兼容接口） | 意图识别、槽位提取与结果生成 |}
| 数据库 | MySQL 8.x | 业务数据存储 |
| 缓存 | Redis | 会话状态、热点数据 |
| 地图 | 高德地图开放平台 API | POI 搜索、路线规划 |
| 认证 | Spring Security + JWT | 用户认证与权限 |
