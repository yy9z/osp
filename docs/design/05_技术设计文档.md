## 二、Agent 模块详细设计

### 2.1 Agent 服务结构

Agent 服务作为独立包放置在 Spring Boot 后端内，包路径：`com.caspar.agent`

| 类名 | 职责 |
|------|------|
| `AgentController` | 接收前端请求，协调 Agent 流程，返回响应 |
| `IntentService` | 调用大模型进行意图识别 |
| `SlotFillingService` | 调用大模型进行槽位抽取，判断缺失参数 |
| `PlannerService` | 根据意图和槽位选择工具调用序列 |
| `ToolExecutorService` | 执行具体工具调用 |
| `ResponseGeneratorService` | 汇总结果，生成自然语言回复和结构化卡片 |
| `ToolRegistry` | 工具注册表，维护所有可用工具的元信息 |
| `LlmClient` | 大模型调用统一抽象层（OpenAI 兼容格式） |
| `AgentSessionManager` | 会话状态管理（Redis 存储多轮槽位） |

### 2.3 意图识别 Prompt 设计

```
System Prompt:
你是一个高校校园智能事务平台的意图识别模块。
你的任务是判断用户输入属于哪个意图类别，并返回 JSON 格式结果。
仅返回 JSON，不要输出其他文字。

意图类别：
- DORM_REPAIR: 宿舍报修相关（空调、灯、网络、门锁等故障）

- REPAIR_QUERY: 查询报修工单状态
- SECONDHAND_SEARCH: 搜索/推荐二手商品
- SECONDHAND_PUBLISH: 发布二手商品
- LOSTFOUND_LOST: 丢了东西，想找
- LOSTFOUND_FOUND: 捡到东西，想找失主

返回格式：
```

### 2.5 工具注册表设计

每个工具在 `ToolRegistry` 中注册，格式如下：

```java
@Component
public class ToolRegistry {
    
    @PostConstruct
    public void register() {
        register(AgentTool.builder()
            .name("dorm_repair")
            .description("提交宿舍报修工单")
            .requiredSlots(List.of("fault_type", "dorm_no", "user_id"))
            .handler(toolArgs -> dormRepairTool.execute(toolArgs))
            .build());
        // ... 其他工具
    }
}
```

工具输入输出格式统一为：

```java
// 工具输入
public class ToolArgs {
    private String toolName;
    private Map<String, Object> params;
    private Long userId; // 当前用户 ID，从安全上下文注入
}

// 工具输出
public class ToolResult {
    private boolean success;
    private String summary;      // 供 ResponseGenerator 使用的简洁摘要
    private Object data;         // 结构化数据（卡片数据）
    private String errorMessage; // 失败时的原因
}
```

### 2.6 多轮对话会话管理

会话状态存储在 Redis 中，Key：`agent:session:{sessionId}`，TTL：30 分钟。

```json
{
  "sessionId": "session_xxx",
  "userId": 1001,
  "intent": "DORM_REPAIR",
  "slots": {
    "fault_type": "空调",
    "dorm_no": null
  },
  "pendingSlots": ["dorm_no"],
  "history": [
    {"role": "user", "content": "我宿舍空调坏了"},
    {"role": "assistant", "content": "好的，请问你的宿舍号是？"}
  ],
  "turnCount": 1
}
```

追问策略：
- 每次只追问一个缺失参数（按 required 列表顺序）。
- 最多追问 3 轮，超过后降级为提示用户手动填写表单。
- 用户输入补充后，合并到 slots 中，重新检验完整性。

### 3.2 核心 API 接口设计

#### Agent 接口

```
POST /api/agent/chat
Content-Type: application/json
Authorization: Bearer {token}

Request:
{
  "sessionId": "session_xxx",  // 首次为 null，系统分配
  "message": "我宿舍空调坏了"
}

Response:
{
  "sessionId": "session_xxx",
  "reply": "好的，请问你的宿舍号是？",
  "askFor": "dorm_no",         // 非 null 时表示正在追问，此时不生成 followUpSuggestions
  "intent": "DORM_REPAIR",
  "extractedSlots": {
    "fault_type": "空调"
  },
  "cards": [],                  // 结果卡片列表（任务完成时非空）
  "usedTools": [],              // 本次调用的工具名列表
  "followUpSuggestions": [     // 动态追问推荐（仅任务完成/阶段性回复时非空）
    "查看工单状态",
    "报修其他设备",
    "联系宿管"
  ]
}
```

**`followUpSuggestions` 生成规则：**
- 当 `askFor` 不为 null（正在多轮追问）时，`followUpSuggestions` 为空数组，不展示追问 Chip
- 当任务完成或给出阶段性回复时，由 `ResponseGeneratorService` 基于当前 `intent` 和工具执行结果生成 3~4 条
- 生成时调用大模型，Prompt 中包含当前意图、执行结果摘要，要求返回 JSON 数组格式的推荐追问列表
- 前端渲染为可点击的 Chip，点击后立即将内容作为下一条用户消息发送

### 3.5 失物相似度计算算法

简单可行的方案（毕业设计阶段）：

```
score = w1 * name_similarity 
      + w2 * color_match 
      + w3 * location_match 
      + w4 * time_proximity

其中：
- name_similarity: 物品名称 TF-IDF 余弦相似度 或 简单字符串包含匹配（0~1）
- color_match: 颜色完全匹配=1, 否则=0
- location_match: 地点字符串相似度（0~1）
- time_proximity: 时间差越小分数越高，公式: max(0, 1 - |dt| / 7) （7天内线性衰减）

权重建议: w1=0.4, w2=0.2, w3=0.25, w4=0.15
```

升级方案（可选）：将物品描述调用大模型 Embedding API 计算向量余弦相似度，存储到 MySQL 的 JSON 字段或使用轻量向量存储。

## 五、Redis 使用设计

| 用途 | Key 格式 | TTL | 说明 |

| 用户 Token 黑名单 | `token:blacklist:{jti}` | Token 剩余有效期 | 退出登录后加入黑名单 |

| 校园 POI 数据 | `nav:poi:all` | 1小时 | 避免频繁查询数据库 |
| 未读消息数 | `msg:unread:{userId}` | 5分钟 | 消息角标数量缓存 |

### 5.2 推荐追问生成设计（FollowUp Suggestion）

**位置：** `ResponseGeneratorService.generateFollowUpSuggestions()` 方法

**触发时机：** 每次 Agent 任务完成或给出阶段性回复时（`askFor == null` 时）

**实现方式：**

```java
// Prompt 模板
String followUpPrompt = String.format("""
    用户刚完成了一次"%s"操作，执行结果摘要：%s。
    请生成3个简短的推荐追问问题（每条不超过10字），
    以JSON数组格式返回，例如：["查看工单状态", "报修其他设备", "联系宿管"]
    仅返回JSON数组，不要其他文字。
    """, intent, resultSummary);

// 调用大模型，解析返回的 JSON 数组
List<String> suggestions = objectMapper.readValue(
    llmClient.chat(List.of(new LlmMessage("user", followUpPrompt))),
    new TypeReference<List<String>>() {}
);
```

## 七、异常处理设计

### 7.1 全局异常处理器

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    
    @ExceptionHandler(AgentException.class)
    public Result<Void> handleAgentException(AgentException e) {
        log.error("Agent exception: {}", e.getMessage());
        return Result.fail("智能助手暂时无法处理，请稍后重试或手动操作");
    }

    @ExceptionHandler(LlmCallException.class)
    public Result<Void> handleLlmException(LlmCallException e) {
        log.error("LLM call failed: {}", e.getMessage());
        return Result.fail("大模型服务暂时不可用，已为您跳转到手动操作页面");
    }
}
```

### 7.2 降级策略

| 故障场景 | 降级行为 |
|----------|----------|
| 大模型 API 不可用 | 返回提示，引导用户使用传统页面操作 |
| 意图识别置信度 < 0.5 | 返回"请更具体描述需求"，附带快捷指令卡片 |
| 工具调用业务异常 | 返回业务错误信息，不影响 Agent 整体服务 |
| Redis 连接失败 | 降级为无多轮记忆模式，单轮处理 |
| 高德地图 API 超时 | 返回"地图服务暂时不可用"，仅显示 POI 文字信息 |
