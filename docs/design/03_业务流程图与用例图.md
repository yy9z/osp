## 二、Agent 核心工作流程图

```plantuml
@startuml agent_workflow
skinparam defaultFontName "Microsoft YaHei"
skinparam backgroundColor #FAFAFA
skinparam activity {
    BackgroundColor #E8F4FD
    BorderColor #1976D2
    FontColor #212121
}

start

:用户输入自然语言请求;

:调用大模型 API\n进行意图识别（IntentService）;

switch (识别意图类型)
    case (宿舍事务)
        :目标工具 = DormTool;
    case (二手推荐)
        :目标工具 = SecondHandTool;
    case (失物招领)
        :目标工具 = LostFoundTool;
    case (校园导航)
        :目标工具 = NavTool;
    case (消息提醒)
        :目标工具 = MessageTool;
    case (未知/混合)
        :返回"无法识别，请重新描述";
        stop
endswitch

:调用大模型 API\n进行参数提取（SlotFillingService）;

if (参数是否完整?) then (完整)
    :任务拆解（PlannerService）\n生成工具调用序列;

    repeat
        :执行工具调用（ToolExecutorService）;
        if (工具调用成功?) then (是)
            :记录工具执行结果;
        else (否)
            :记录失败原因\n尝试降级处理;
        endif
    repeat while (还有待执行工具?) is (是)
    -> 否;

    :结果汇总（ResponseGeneratorService）\n生成自然语言回复 + 结构化卡片;

    :返回前端展示;
else (缺失)
    :生成追问话术\n向用户追问缺失参数;

    :等待用户补充输入;

    :合并参数，重新检验完整性;
    note right: 最多追问 3 轮\n超过则提示用户手动填写

    -> 参数是否完整?;
endif

stop
@enduml
```

    :点击联系对方（站内消息）;
    :双方确认物品;

    if (确认找回?) then (是)
        :标记失物状态为"已找回";
    else (否)
        :继续等待其他匹配;
    endif
else (否)
    :继续等待新拾物/失物记录;
endif

## 七、用户登录与权限验证流程图

```plantuml
@startuml auth_flow
skinparam defaultFontName "Microsoft YaHei"

|用户|
start
:访问任意页面;

|前端|
:检查本地 Token 是否存在;

if (Token存在?) then (是)
    :携带 Token 发起 API 请求;

    |后端(Spring Security)|
    :解析 JWT Token;

    if (Token有效?) then (是)
        :提取用户身份与权限;
        :放行请求，执行业务逻辑;
    else (否)
        :返回 401 Unauthorized;
        |前端|
        :清除本地 Token\n跳转登录页;
    endif
else (否)
    |前端|
    :跳转登录页;
    |用户|
    :输入账号密码;
    |后端|
    :验证账号密码;

    if (验证通过?) then (是)
        :生成 JWT Token 返回前端;
        |前端|
        :保存 Token 到 localStorage;
        :跳转首页;
    else (否)
        :返回错误提示;
    endif
endif

stop
@enduml
```

## 九、Agent 工具调用序列图

```plantuml
@startuml agent_sequence
skinparam defaultFontName "Microsoft YaHei"

actor 用户
participant "前端(Vue3)" as Frontend
participant "AgentController" as AC
participant "IntentService" as IS
participant "SlotFillingService" as SFS
participant "PlannerService" as PS
participant "ToolExecutorService" as TES
participant "业务工具(DormTool等)" as Tool
participant "ResponseGeneratorService" as RGS
participant "大模型API" as LLM

用户 -> Frontend: 输入自然语言
Frontend -> AC: POST /api/agent/chat\n{sessionId, message}

AC -> IS: identifyIntent(message)
IS -> LLM: 发送意图识别 Prompt
LLM --> IS: {intent, confidence}
IS --> AC: IntentResult

AC -> SFS: extractSlots(message, intent)
SFS -> LLM: 发送槽位抽取 Prompt
LLM --> SFS: {slots, missingSlots}
SFS --> AC: SlotResult

alt 槽位不完整
    AC --> Frontend: {askFor: "请问宿舍号是？"}
    Frontend --> 用户: 展示追问
    用户 -> Frontend: 补充输入
    Frontend -> AC: POST /api/agent/chat\n{sessionId, message}
    note over AC: 合并槽位并重新检验
end

AC -> PS: planTasks(intent, slots)
PS --> AC: [ToolCall1, ToolCall2, ...]

loop 逐个工具调用
    AC -> TES: execute(toolCall)
    TES -> Tool: 调用对应业务API
    Tool --> TES: 业务执行结果
    TES --> AC: ToolResult
end

AC -> RGS: generateResponse(intent, slots, toolResults)
RGS -> LLM: 发送结果生成 Prompt
LLM --> RGS: 自然语言回复文本
RGS --> AC: {text, cards, followUpSuggestions}

AC --> Frontend: {reply, cards, usedTools, followUpSuggestions}
Frontend --> 用户: 展示回复 + 结果卡片 + 推荐追问 Chip

@enduml
```

## 十一、失物招领 4 子模块业务流程图（重构）

```plantuml
@startuml lostfound_4tab_flow
skinparam defaultFontName "Microsoft YaHei"

start

if (用户操作类型?) then (查看公共信息)
    if (想看哪类公告?) then (寻物公告)
        :进入"寻物公告"Tab\n（全校已发布的"我丢了"帖子）;
        :按类型/关键词筛选浏览;
        if (发现可能认识的物品?) then (是)
            :点击联系失主（站内消息）;
        endif
    else (招领公告)
        :进入"招领公告"Tab\n（全校已发布的"我捡到了"帖子）;
        :按类型/关键词筛选浏览;
        if (是自己丢失的物品?) then (是)
            :点击联系拾主（站内消息）;
            :双方确认，失主标记"已找回"\n拾主标记"已归还";
        endif
    endif
else (发布我的信息)
    if (我是失主) then (我丢了)
        :输入自然语言描述\n（可通过Agent自动填写）;
        note right: Agent自动提取\n名称/颜色/地点/时间

        :确认并发布到"寻物公告";

        :系统在"招领公告"中自动搜索\n相似物品候选列表;

        if (找到相似招领?) then (是)
            :展示候选匹配列表\n（相似度排序）;
            if (相似度超过阈值?) then (是)
                :系统向双方主动推送通知;
            endif
            :失主点击发消息联系拾主;
        else (否)
            :等待后续新增招领记录;
            :系统后台持续匹配并通知;
        endif

        :成功找回后\n在"我的失物"中标记"已找回";
    else (我捡到了)
        :填写物品信息\n（可通过表单或Agent语言填写）;

        :发布到"招领公告";

        :系统在"寻物公告"中自动搜索\n相似失物候选列表;

        if (找到相似寻物?) then (是)
            :展示候选匹配列表;
            :拾主联系失主;
            :归还成功后\n在"我的招领"中标记"已归还";
        endif
    endif
else (管理我的发布)
    if (查看哪类?) then (我的失物)
        :进入"我的失物"Tab\n仅展示当前用户发布的寻物帖;
        :可修改/删除/标记已找回;
    else (我的招领)
        :进入"我的招领"Tab\n仅展示当前用户发布的招领帖;
        :可修改/删除/标记已归还;
    endif
endif

stop
@enduml
```

## 十二、动态追问推荐机制流程图（新增）

```plantuml
@startuml followup_flow
skinparam defaultFontName "Microsoft YaHei"

actor 用户
participant "前端对话区" as Chat
participant "ResponseGeneratorService" as RGS
participant "大模型API" as LLM

用户 -> Chat: 发送消息

Chat -> RGS: 工具执行完毕，生成回复

RGS -> LLM: 调用大模型生成自然语言回复

LLM --> RGS: 回复文本

RGS -> RGS: 基于当前意图+工具结果\n生成3~4个推荐追问选项\n(followUpSuggestions)

note over RGS
  生成逻辑示例:
  - DORM_REPAIR 完成 →
    ["查看工单状态", "报修其他设备", "联系宿管"]
  - NAVIGATION 完成 →
    ["查看路线详情", "换骑行方案", "附近还有哪些地点"]
  - LOSTFOUND_LOST 完成 →
    ["立即发布寻物", "查看相似招领", "补充丢失时间"]
end note

RGS --> Chat: {reply, cards, followUpSuggestions}

Chat --> 用户: 展示回复+结果卡片\n底部显示推荐追问Chip

alt 用户点击推荐Chip
    用户 -> Chat: 点击"查看工单状态"
    Chat -> Chat: 自动填充并发送该文本
    Chat --> 用户: 开始新一轮对话

else 用户手动输入
    用户 -> Chat: 手动输入下一条消息
end

@enduml
```
